# GitHub Profile Guidelines

## Repository Purpose

This repository contains Cesar's public GitHub profile in English (`README.md`) and Spanish (`README_es.md`). Its audience is technical recruiters, hiring managers, and engineers.

## Canonical Content

- Use `../source/` as the canonical source for professional facts, positioning, skills, and verified projects.
- Do not introduce facts that are absent from `../source/` unless Cesar explicitly confirms them and the canonical source is updated first.
- If the profile conflicts with `../source/`, flag the conflict instead of silently choosing one version.
- Do not describe project ideas or undocumented repositories as completed or production-ready work.

## Positioning and Style

Maintain the primary positioning:

> Senior Backend / Full-Stack Engineer | Python, FastAPI, AWS | Distributed Systems & AI

- Lead with backend engineering, Python, cloud, distributed systems, reliability, and AI-enabled applications.
- Treat frontend and mobile technologies as supporting full-stack breadth.
- Prefer concrete engineering capabilities and verified project evidence over generic claims.
- Avoid badges, decorative clutter, exhaustive technology lists, unsupported metrics, and phrases such as "passionate developer" or "rockstar developer."
- Keep the profile concise and easy to scan.

## Bilingual Content

- Keep `README.md` and `README_es.md` semantically aligned.
- Use natural language in each version rather than literal word-for-word translation.
- Preserve links, project status, factual claims, and section order across both versions unless there is a clear audience reason not to.
- Update both files when changing shared professional content.

## Validation and Git

- Check Markdown structure, links, and consistency between both language versions after edits.
- Inspect the diff before considering changes complete.
- Do not commit or push unless explicitly requested.
- Preserve unrelated worktree changes.
